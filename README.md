# Funnel Service #

Funnel Service records affiliate funnel activity and keeps it queryable. The HTTP server accepts abandoned-lead posts and Everflow webhooks for clicks, conversions, offers, affiliates, and advertisers. A command-line client syncs those same records from the Everflow API across two networks, matches abandoned leads back to clicks, and writes everything to Postgres through [sqlc](https://sqlc.dev). The server rolls click and conversion activity into hourly stats.

Ingestion covers:

- Abandoned leads, matched to a known offer URL
- Offers, offer URLs, affiliates, and advertisers
- Clicks and conversions, from webhooks or a dated API sync

## Setup ##

Local code execution relies on godotenv to read from a .env and populate the env variables.
The binary will search the current path for the .env file.

## Database ##

The compose.yml file can be used to bring up a docker instance that will host the database.
It will read the values from the .env file to automatically build the Postgres db.

```bash
docker compose up -d
```

Under the hood, sqlc is used to manage the queries and models and has been included in the go toolchain; Alternativly use go install or brew (osx) to install the binary.

#### To rebuild the SQL models generated by sqlc:

```bash
cd internal/db/config
go tool -modfile=tools.mod sqlc generate
# or, use the Makefile #
make
```

*Running the above command will take a moment on first run since go will need to build the tool before it can execute.*

## Server ##

Requests to /abandoned/ will store the cookies & payload body in the database if the landing_page is found among the available offer_urls.
The /webhooks/ endpoints are used for

```bash
go run cmd/server/main.go
```

### Example: ###

```bash
curl --request POST \
  --url http://localhost:8000/abandoned \
  --header 'Content-Type: application/json' \
  --data '{
    "landing_page": "https://example.com/quiz/?s1=112&s2=432&s3=sample-click&s4={affiliate_name}&s5={offer_url_name}",
	"session_length": 26,
	"step_number": 5,
	"cookies": "[
		{"s1": 112},
		{"s3": "sample-click"}
	]",
	"body": "{
		"email": "testperson@example.com",
		"first_name": "test",
		"last_name": "person",
		"ip": "192.168.10.154",
		"phone_cell": "5551235432",
		"date_of_birth": "1981-01-01",
		"smoker": false
	}"
}'
```

## Client ##

### Sync ###

Sync data from Everflow into the database.

```bash
# Sync all
go run cmd/client/main.go sync
```

```bash
# Sync Clicks and Conversions support --start and --end for datetime range and --network for Everflow account selection
go run cmd/client/main.go sync:clicks --start "YYYY-mm-dd HH:ii:ss" --end "YYYY-mm-dd HH:ii:ss" --network primary|secondary
go run cmd/client/main.go sync:conversions --start "YYYY-mm-dd HH:ii:ss" --end "YYYY-mm-dd HH:ii:ss" --network primary|secondary
```

### Performance ###

Check the server availability.
This will bombard the server with 128 simultaneous requests and summarize the output.

```bash
go run cmd/client/main.go performance -url "http://localhost:8000/health" -size 128
```
